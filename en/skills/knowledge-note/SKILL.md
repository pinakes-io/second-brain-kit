# Knowledge note (draft 0.1)

## Goal
What we research together does not get lost with the chat. There is exactly one note per topic in the folder `Knowledge`, with sources, date and status. The `00_Knowledge_Index` keeps the overview. Later chats find the knowledge there.

## When (decide silently, do not announce)
File when at least one of these applies:
- You researched with sources or explained at length, and I will need the topic again in the coming weeks.
- The result influences a decision or an application.
- I say "file as knowledge" or "remember this as knowledge".

Do not file: word meanings, exercises, conversations, feelings, one-off follow-up questions, single letters or appointments (they belong in the State or `Journal`), planning the week. If you are unsure, offer it in one sentence ("Shall I file this as knowledge?") and do not ask again on a no.

Never file: anything listed under "Limits" in `00_Status`, also health data, data of third parties and my personal assessments (they belong in the profile when I mention them).

## Procedure
1. Read `00_Knowledge_Index`. Is there a note on this or a very close topic? Also search the folder for the name.
2. If yes: extend that note, do not create a second one. If old and new text contradict each other, show both briefly and ask which one applies.
3. If no: create a new note in the folder `Knowledge`. Name `Topic_Keyword` without spaces, for example `Funding_Training`. Use topic words that already exist in the index before inventing new ones. Never create at top level.
4. Check numbers, deadlines, amounts and rules with `fact-check` before filing. What you cannot prove gets ⚠ unchecked.
5. Write the note on at most one page: title · short version (two to three sentences) · meaning for me (from `01_Profile`; if something does not fit me, say so) · details as bullet points · sources with retrieval date and status · uncertain or to clarify · related notes · last update. Longer: split into two notes and link them.
6. Also enter hard facts (number, deadline, amount) in the `Fact-Ledger`. The note names the ledger ID. The ledger stays the source for numbers.
7. Link in both directions: in every related note name the other one under "Related notes".
8. Update the index, one line per note: note · topic · as of (date) · reference. Replace an existing line, do not add a duplicate.
9. Without write access output an update block and say that I have to enter it myself.
10. Then answer with one short line, for example "Filed in Knowledge (topic …)". No list of what you wrote unless I ask.

## Using and maintaining notes
- When a topic starts for which a note exists, read the note first via the index, then answer. Do not research again if the note is current.
- If a note on money, deadlines or rules is older than 90 days, check it with `fact-check` before use and update "last update" and the index.

## Rules
- One note per topic. Search first. No copies like "_old" or "_new". Delete or rename nothing without my explicit request.
- If I say "do not note" or "skip", file nothing and do not ask.
- Check line only if facts were checked: `🔎 Read: 00_Knowledge_Index ✓ · official sources ✓ · 📝 Filed: Knowledge, index`.
